Deathlink — référence complète

Les règles, les valeurs et les exceptions de Deathlink. La lecture complète, pour arrêter d’accuser la malchance.

Version 0.13.0 : explicite et hérité

23 paramètres généraux et 7 profils. Un champ absent du YAML prend la valeur du constructeur du mod. Les tables montrent ces valeurs effectives, en signalant celles héritées. Les règles sont relevées dans les fichiers du pack et vérifiées dans la DLL installée ; aucune règle de jeu n’a été changée.

Facteur de progression et arrondis

Le facteur utilisé pour la perte et les budgets vaut clamp(niveau Deathlink / 100 ; 0,01 ; 1). Le bonus additionnel de cette fonction est 0 dans ces appels. La perte vaut Lerp(MaxSkillLossPercentage, MinSkillLossPercentage, facteur). Le nombre de pièces vaut RoundToInt(MinEquipmentKept + (MaxEquipmentKept − MinEquipmentKept) × facteur). Les budgets hors équipement et de choix utilisent la même interpolation.

RoundToInt arrondit au plus proche ; à mi-chemin, il choisit l’entier pair. Deathbound donne donc 0 pièce à 12,5, 2 à 37,5 et 2 à 62,5. Dès un niveau entier 13, 1 pièce devient disponible ; 38 donne 2, 63 donne 3 et 88 donne 4. L’accès aux repas a ses propres seuils : 30 exactement efface tout, 60 exactement retire un repas, 90 exactement conserve tout.

La perte multiplie le niveau courant et remet m_accumulator à zéro pour les compétences traitées. Deathlink est ajouté à la liste d’exemption. Le patch interrompt la routine si l’effet SoftDeath / No skill drain est présent. Il remplace la routine vanilla au lieu d’ajouter une deuxième perte vanilla identique. Les autres patchs de compétences, notamment NorseDemigods, doivent être considérés séparément pour leurs interactions.

Gain d’action B = 20 × Δboss + 5 × Δvictimes + 0,5 × Δconstructions + 0,1 × Δarbres + 0,1 × Δminage + 0,8 × Δfabrications/améliorations. Gain transmis = B × max(0, ln(t)/10) × DeathSkillRate ; t est m_timeSinceDeath en secondes. Le pas de compétence est 0,1. Le moteur multiplie encore par Game.m_skillGainRate et les éventuels modificateurs de compétences. Seuil suivant = 0,5 × floor(niveau + 1)^1,5 + 0,5 ; lors d’un niveau gagné, l’accumulateur est remis à zéro.

SkillInfluence : pour un bonus supérieur à 1, multiplicateur = 1 + (BonusModifier − 1) × Clamp01(facteur). Si BonusModifier ≤ 1, la routine ScaleTowardsOne renvoie directement la valeur. Les entrées de gain de compétence correspondantes sont additionnées ; deux entrées à 1,05 peuvent donc donner 2,10. Une collection vide signifie absence de modification, pas absence d’XP. Les bonus de butin ont un tirage indépendant par entrée.

Les cinq modes ItemLossStyle

La destination d’un objet sauvé et sa survie sont deux décisions différentes. « Sauvé dans la tombe » ne signifie pas « tous les objets sont sauvés » dans un profil DeathlinkBased.

Modes de mort

Modes de mort
ValeurTraitement
NoneNe détruit pas les objets ordinaires. ItemSavedStyle et EquipmentSavedStyle déterminent leur destination ; la liste d’exclusion conserve son traitement distinct.
DestroyNonWeaponArmorSauve les catégories reconnues comme équipement, détruit les autres objets ordinaires. Malgré son nom, la reconnaissance inclut outils, accessoires et bijoux.
DeathlinkBasedBudget de survie lié à la compétence. Les objets ordinaires non sauvés sont détruits. Une partie peut être choisie si les choix sont actifs ; le complément est aléatoire.
DestroyAllDétruit le pool d’objets ordinaires, y compris l’équipement. Les objets de ItemsNotSkillChecked suivent encore leur action séparée ; dans le pack, ils rejoignent la tombe.
ChooseEquipmentNe détruit rien avec l’action d’exclusion actuelle. Envoie les objets hors équipement à la tombe. Si le matériel dépasse le budget, tout ce matériel va à la tombe puis le propriétaire en reprend une sélection au respawn. Sinon ce matériel reste sur soi. ItemSavedStyle, EquipmentSavedStyle et EnableItemSavingChoices ne contrôlent pas cette reprise.

La voie aléatoire DeathlinkBased distingue budgets de matériel et d’objets ; la voie avec sélection utilise un budget total et un nombre limité de choix, complété par le tri du mod. Les sélections portent sur les entrées ItemData de l’inventaire : une pile est une entrée, pas un tirage par unité. La reprise ChooseEquipment vérifie le propriétaire et retire réellement les pièces de la tombe ; une tombe occupée, disparue ou déjà vidée peut empêcher ou réduire la reprise.

Règles, sauvegardes et synchronisation

DeathChoices.yaml contient les sept profils. MidnightsFX.Deathlink.cfg contient les 23 paramètres généraux. Le serveur synchronise les règles aux clients ; des profils proposés identiques ne signifient pas que tous les personnages choisissent le même profil. DefaultDeathChoice vide affiche le choix. AllowedDeathChoiceChanges = 1 autorise ensuite un changement depuis le compendium.

UsePrivateKeysForDeathChoice = true : la clé du choix est stockée sur le personnage. CharacterSettings.yaml est une sauvegarde alternative, consultée lorsque cette option vaut false ; ce fichier ne définit pas les règles des profils. leaderboard.yaml stocke les statistiques de classement. Le guide ne reproduit pas les identifiants ni les statistiques personnelles des joueurs. Les fichiers localizations/*.json définissent les libellés d’interface, pas les pénalités.

La clé Progressif identifie Deathbound. Renommer DisplayName change seulement le libellé ; renommer ou supprimer Progressif déplace les personnages concernés vers le repli Vanilla. Un administrateur peut utiliser dl-reset-choice NomDuJoueur ou son identifiant, puis le joueur rouvre son inventaire. La réinitialisation ne sert pas à modifier les règles du profil.

Almanac et WackyMMO : les options n’agissent que si les intégrations sont chargées. Perte d’XP externe = −RoundToInt(niveau externe × taux de perte × 500 × échelle de perte). Gain externe = RoundToInt(gain d’action après bonus de survie × échelle de gain). Le multiplicateur DeathSkillRate est appliqué après ce calcul dans la voie de progression Deathlink. Ces intégrations ne constituent pas une intégration explicite de NorseDemigods.
