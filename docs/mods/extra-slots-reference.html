Les conditions exactes

Les quickslots et utilitaires supplémentaires testent les listes de clés et d’objets : toutes deux vides → aucune condition ; une seule remplie → sa condition doit être vraie ; toutes deux remplies → clé OU objet suffit. Plusieurs entrées dans une liste sont des alternatives. Les clés « Global keys » peuvent être reconnues sur le monde ou sur le personnage ; les objets doivent avoir été découverts personnellement.

Un quickslot existe seulement si son index est inférieur à Amount of quick slots ; sa condition doit être remplie, et tous les quickslots précédents doivent être accessibles. Un utilitaire supplémentaire exige aussi la connaissance du slot utilitaire de base et l’accès à tous les ajouts précédents. Les slots nourriture et munitions exigent leur activation, leur éventuelle clé et leur découverte de type. Les divers exigent miscSlotsEnabled, au moins un quickslot accessible, et une catégorie nourriture/munitions (premier divers) ou les deux (second divers).

Calcul des lignes allégées

First row index = −2 vise les deux dernières lignes de l’inventaire principal. Only extra rows = false permet d’affecter les lignes natives. La condition utilise des clés personnelles OU des découvertes, et n’est pas identique à une simple clé de boss du monde. Avec Weight factor = 0.5, le poids de chaque objet de ces lignes est multiplié par 0,5 dans le calcul du poids total porté.

Si First row index = 0, la fonction est désactivée ; une valeur positive n vise les lignes à partir de la n-ième, numérotées depuis 1. Une valeur négative −n vise les n dernières lignes. La réduction des lignes est testée avant les coefficients des cases dédiées ; dans le pack, ces derniers sont tous à 1. Les valeurs de progression des lignes d’inventaire sont sans effet lorsque Inventory rows progression enabled = false.

Règles de jeu et préférences locales

Les paramètres marqués [Synced with Server] sont contrôlés par le serveur selon la politique ConditionalConfigSync : quantités, progression, admissibilité, poids et règles de mort notamment. Touches, positions, libellés, couleurs, aides et plusieurs réglages de présentation restent locaux par défaut. Lock Configuration est toujours contrôlé par le serveur.

Le fichier ConditionalConfigSync.SyncPolicy.cfg du pack ne contient actuellement que des commentaires : aucun forçage supplémentaire de politique n’est déclaré. Une règle + impose le contrôle du serveur, une règle − rend un réglage local ; une règle exacte prime sur une règle de section. Distribuer le même pack initialise les mêmes touches, mais ne prouve pas qu’elles sont verrouillées pour tous les joueurs.

La sauvegarde des cases conserve le dernier état enregistré avec le personnage, pas toutes les versions historiques. L’auteur indique qu’un chargement sans le mod peut faire disparaître les objets de ces cases ; sa restauration dépend du retour du mod et de sa sauvegarde. Avant de retirer un mod d’inventaire, déplacer les objets vers des cases ordinaires ou des coffres reste le geste pratique à retenir. Les compatibilités Epic Loot, BowsBeforeHoes, Recycle_N_Reclaim ou Valheim Radial ne prouvent pas que ces mods sont installés.

Configuration shudnal.ExtraSlots.cfg et documentation de la version installée 1.2.17 ; méthodes SlotsProgression, Slots et LightenedSlots de la DLL, ainsi que le calcul du poids porté. Les valeurs des copies RPG et locale correspondent lors de cette lecture. Relevé le 9 octobre 2026.
